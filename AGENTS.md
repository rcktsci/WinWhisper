# AGENTS.md

Правила работы над WinWhisper. Для людей и для агентов.

## Релизы

- **По умолчанию релизим только в GitHub**: поднять версию, собрать, `--selftest`, тег `vX.Y.Z`,
  дождаться зелёного CI и опубликованного ассета. Всё.
- **Публикация в winget — только по явному сообщению пользователя.** Никогда не отправлять
  `wingetcreate submit/update`, не создавать и не править PR в `microsoft/winget-pkgs`
  по своей инициативе, даже если новая версия «давно просится».
- Выпуск 1.1.10 был отозван по этой причине: релиз сделали, не спросив. Не повторять.

## Неприкосновенное

- **Опубликованные релизы и их ассеты не переписываются.** Никаких повторных заливок exe,
  удаления тегов, force-push после публикации: хеш в winget-манифесте привязан к файлу.
  Нужна правка — выпускается новая версия.
- Версию поднимать в трёх местах: `kVersion` в `src/app.cpp`, `VALUE "FileVersion"` и
  `"ProductVersion"` в `src/res/WinWhisper.rc`, `assemblyIdentity` в `src/res/WinWhisper.manifest`.

## Как работать

- **Сначала объяснить, что собираешься делать, — потом код.** Пользователь хочет видеть план
  до правок, особенно если это меняет поведение ежедневного инструмента.
- **Только заказанные правки.** Ничего «додуманного»: ни новых жестов, ни настроек, ни откатов,
  о которых не просили.
- Коммиты — по-русски, с описанием «что и почему»; README и интерфейс — по-русски.
- Перед публикацией — проверка по факту (сборка, `--selftest --offline`, живой прогон),
  а не «должно работать».

## Проверки

```powershell
& 'X:\Microsoft Visual Studio 2026\MSBuild\Current\Bin\MSBuild.exe' WinWhisper.vcxproj `
  /p:Configuration=Release /p:Platform=x64 /m /v:m /nologo
.\x64\Release\WinWhisper.exe --selftest --offline
```

Перед сборкой закрыть работающий экземпляр: `WinWhisperFindWindowW('WinWhisperHiddenHost')` +
`WM_CLOSE`, иначе линковка не перезапишет exe.
